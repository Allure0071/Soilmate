## 2. 当前网站评估

| 领域 | 已有能力 | 差距与判断 |
| --- | --- | --- |
| 导航与地图 | 首页、探索数据、Gold Dataset、分析中心、证据追溯入口；Leaflet 地图、5/1 km 切换、指标目录、点位详情、参考分区 | 页面入口与任务目标混合；正式指标瓦片缺失，研究预览不能表示已完成全国正式图层 |
| 点位结果 | 核心六项和其他指标、来源/缺失提示；Base-SHI/N+X 评价占位 | 没有可核验的存量健康分和正式区域映射；网格预测值须与实测样本分开展示 |
| 数据中心 | 5/1 km `points`、`indicators`、`meta` 只读分页浏览与图层搜索 | 当前是技术型 SQL 浏览器，缺数据集级目录、业务筛选、许可审查、授权下载与记录 |
| 用户与研究 | 邮箱密码注册/登录、会话；项目、导入数据、样本、任务、行动、报告版本存在 SQLite | 无手机号/身份角色流程；下载与收藏历史缺失；研究数据库不等于完整个人中心 |
| 检测评价 | Soiledge 手填及 XLSX 批量估算、CSV 结果；本机 Ollama 可生成说明 | 现有分数是旧方法研究估算；未形成地区+作物 N+X 基线、同一样本微生物校正及正式诊断 PDF |
| Agent/证据 | 科研 Agent 候选动作、局部执行日志；KO 公开案例 | Agent 不是完整自动调度器；公开 KO 案例与地图点位未配对，不能推断田块微生物状态 |
| 知识与后台 | 少量静态说明、研究页面 | 独立知识库、工具箱、内容审核和管理员工作台尚未实现 |
| 交互与视觉 | 地图主舞台、左侧图层抽屉、右侧详情；移动端抽屉/面板 | 需统一导航和术语、密集表格的移动呈现、空状态与权限提示；CSS 存在多套根变量，设计系统需收束 |

### 关键结论

1. 当前是**研究演示与开发底座**，已有地图、数据浏览和研究记录的可用代码，但不是四模块产品的完成版。
2. 先把“数据是什么、能否展示、能否下载、能否评分”做成明确状态；不要让“有栅格值”自动变成“实测”或“健康诊断”。
3. 最难的依赖不是页面，而是正式瓦片、数据授权、地区/作物基线、独立健康真值和同一样本微生物证据。

## 3. 产品目标与用户

目标：让访客理解空间数据；让获授权用户检索和下载可共享数据；让用户提交自身检测数据并获得可追溯的研究评价；让管理员管理数据、知识和模型版本。

| 角色 | 主要任务 | 权限原则 |
| --- | --- | --- |
| 游客 | 浏览公开图层、知识文章和工具 | 只能访问公开且已审核发布的资源 |
| 注册用户 | 保存偏好与收藏、提交自有数据、查看自己的任务 | 默认只能看本人上传数据与本人任务 |
| 数据授权用户 | 按许可下载指定数据集 | 每次导出均记录范围、版本、用途和时间 |
| 科研/农技用户 | 使用进阶筛选、查看方法与证据 | 角色不自动等于下载许可，仍按数据集授权 |
| 数据审核员/管理员 | 审核数据、内容、模型版本和日志 | 独立管理入口、最小权限、操作可追溯 |

手机号及身份是否必填、如何验证身份与数据授权规则尚需产品/管理方决策；在确定前不能把“填写身份”直接当作授权依据。

## 4. 功能需求与验收

优先级：P0 为首个可交付产品版本；P1 为下一阶段；P2 为依赖科研验证或长期运营的能力。

### 模块一：全域数据可视化探索

| ID | 优先级 | 需求与验收要点 |
| --- | --- | --- |
| M1-01 | P0 | 图层目录按土壤/环境/农业等分类检索；每层显示类型、单位、年份、土层、分辨率、覆盖范围、来源和状态。仅已发布瓦片可选为正式全国图层；缺瓦片给出清楚状态。 |
| M1-02 | P0 | 地图支持单图层主显示、透明度、图例和点位点击；坐标、网格 ID 与数据来源可回溯。支持空值、无覆盖和接口错误。 |
| M1-03 | P0 | 右侧详情将“网格预测/派生值”“实测样本”“合成测试值”分组标识；原始值展示单位、时间、土层和缺失状态。 |
| M1-04 | P1 | 已核验的存量评价结果可展示模型版本、适用区域、结果状态、限制和来源；无合格结果时显示“未形成可发布评分”。 |
| M1-05 | P1 | 点位/图层跳转到资源中心并带上数据集 ID 与空间范围；未获下载许可时仅展示申请或说明。 |

### 模块二：标准化数据库资源中心

| ID | 优先级 | 需求与验收要点 |
| --- | --- | --- |
| M2-01 | P0 | 建立数据集目录和版本页，记录来源、采样/制图方法、单位、时间、地理覆盖、许可、质量等级、更新日期和负责人。 |
| M2-02 | P0 | 按区域、指标、时间筛选；作物类型仅对有作物字段的数据集开放。筛选条件与结果数量一致，可清空、复用。 |

### 模块三：AI 土壤智能健康评价

| ID | 优先级 | 需求与验收要点 |
| --- | --- | --- |
| M3-01 | P0 | 用户建立地块/任务，录入地区、作物、采样时间、深度、检测机构、指标及单位；上传 CSV/XLSX 模板。校验必填、范围、单位、重复样本及缺失项。 |
| M3-02 | P0 | 后端保存原始上传文件、规范化记录、校验报告与任务状态；任务归属本人，重开和换设备后可复看。原始值不可被计算结果覆盖。 |
| M3-03 | P0 | 输出“可评价/证据不足/待人工复核”门控；缺地区/作物基线、单位不明或样本证据不足时停止正式评分。可保留独立的研究估算入口。 |
| M3-04 | P1 | 经科研验收的 N+X 模型按地区、作物、指标版本匹配；记录基线 ID、权重、转换、缺失处理、区划版本、算法版本与适用条件。与模型域外输入分开处理。 |
| M3-05 | P2 | 微生物氮循环模块仅在**同一样本身份、采样时间与来源**核验通过，并有 QC/注释质量与独立验证规则时参与校正；否则只做并列证据展示，校正值为空。 |

| M3-07 | P1 | Agent 调度每一步有输入输出摘要、工具/模型版本、规则、耗时、失败原因和人工覆核记录；生成文本不能改写计算原值。 |

## 5. 数据与科学发布门槛

所有数据对象均需 `source_type`（实测/模型预测/派生/合成）、`source_uri`、版本、许可、空间/时间/土层范围、单位、质量状态和审核状态。地图格点不是独立田间样本。导出与评分分别设许可门槛和科学门槛。

N+X 发布前至少确认：目标九区边界及地区映射；N/X 指标定义、单位和来源；训练与独立验证样本；折内筛选和空间留出；跨区/跨作物适用条件；缺失处理、阈值与版本回退。当前研究预览图层和 Z01 参考区划不能代替这些验收。

微生物校正发布前至少确认：土壤与测序数据的同一样本配对、同 Run 质控、功能注释质量、独立真值以及校正前后增益。未满足时报告显示“未参与评分”。

## 6. 交付顺序与待决策

1. **P0 产品底座**：统一导航与数据状态、数据集目录、筛选、授权导出、下载记录；上传与任务保存；空白/错误/无证据状态。
2. **P1 工作流完善**：点位跳资源、个人中心、收藏、知识库与工具、PDF 报告、Agent 证据化说明；正式模型只在验收后开通。
3. **P2 科研校正与运营后台**：微生物增量校正、模型/标注管理、审核台和全链路审计。

待产品负责人确认：目标用户和首发地区；哪些数据集允许公开/授权下载；手机号是否必需；数据保留与删除规则；正式评分所依据的模型与版本；后台审核责任人。这些问题不妨碍先开发 P0 的通用底座。
