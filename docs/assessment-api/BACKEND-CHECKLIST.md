# 给后端同学的确认清单

这是前端根据平台流程图 v9 准备的 `0.1.0-draft`，**尚未代表双方已达成一致**。请先确认 P0，再排 P1；可以直接在本文件写调整意见。

前端负责页面、请求层与 Mock；后端负责真实接口、数据库、N+X、微调千问和多 Agent。接口详情见 [README](README.md)、[OpenAPI](openapi.json) 和 [虚构示例](examples.json)。

## A. P0：快速试用优先确认

- [ ] 基础地址采用 `/api/assessment`，开发继续走同源 Vite 代理。
- [ ] 沿用现有账号 Cookie、`GET /api/auth/me` 和 CSRF；新健康接口在后端补齐权限校验。
- [ ] 指标字典提供稳定代码、单位、方法、别名和版本；输入、地图字段与模型特征如何映射由后端确认。
- [ ] 一项有效实测即可分析；少于推荐项数不阻断。缺少方法/单位影响判读范围，不默认补造其他指标。
- [ ] 新成功响应使用 `data / request_id / data_origin`，新错误用结构化 error；旧账号格式保持不变。
- [ ] 会话及检测记录可以读取，刷新后不重复创建分析。
- [ ] 分析任务返回 202 + task_id，通过 GET 查询；确认六种状态及 result 类型对应关系。
- [ ] 追问保存到同一会话，由后端读取上下文并创建 followup；支持解释原结果，不必每问都全量重跑。
- [ ] 综合分数可空；评价、问题、可能成因、证据、建议和补测分别返回。
- [ ] 确认写请求 `Idempotency-Key` 的实现方式、重放行为和保留时长。
- [ ] 确认轮询间隔、超时处理、429/503 和失败后重试方式。

P0 范围：账号状态、指标字典、创建/恢复会话、保存/读取实测、创建/查询任务、读取/发送消息，共 10 个操作。

## D. 共同验收的最小场景

1. 登录 → 一项指标 → 异步分析 → 有范围说明的评价与决策 → 同会话追问。
2. 刷新恢复输入和结果；其他账号无权读取。
3. 文件中两个样本形成两份记录，不合并；错误行不被静默吞掉。
4. 同一地块至少两个时点；当前时点补测不冒充下一轮。
5. 模型断开/任务失败/中断/版本冲突均有真实错误状态，界面保留输入。
