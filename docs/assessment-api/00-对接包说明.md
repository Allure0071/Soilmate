# Soilmate 健康评价：后端接口对接说明

日期：2026-11-02。版本：0.1.0-draft，待前后端共同确认。

## 这次要做什么

我们准备按照平台流程图 v9 改造健康评价功能。前端由我这边负责，真实接口、数据库、模型和算法由后端同学负责。这个压缩包用于先约定双方如何传数据，让前端可以使用 Mock 同时开发。

包里的接口和示例目前都是草案，不要求后端照搬所有技术细节。有不合适的字段、路径或状态可以提出修改，双方确认后统一更新。

## 功能分为两条路径

**快速试用**：登录 → 输入检测指标 → 自主微调千问分析 → 返回评价、问题分析和管理建议 → 继续追问。

**深度分析**：地块、作物与背景 → N+X 推荐指标集合及多时点检测方案 → 自主录入实测 → 多 Agent 协作 → 评价、问题分析和决策 → 执行反馈 → 后续检测与方案调整。

两种模式都使用团队自主微调的千问模型。快速模式直接调用模型；深度模式通过统筹 Agent 组织专业角色。前端只负责请求、状态和结果展示，不直接调用模型服务。

## 第一批先接哪些功能

优先完成快速试用这一条闭环：

1. 复用现有登录，提供当前账号和请求校验信息。
2. 提供指标清单，包括代码、名称、单位和方法。
3. 创建、恢复会话，保存、读取本次检测值。
4. 创建分析任务，提供任务进度和结构化结果。
5. 保存追问、读取上下文，返回后续答复。

第一批共 10 个接口操作，其中账号状态接口已经存在。地块、N+X、多 Agent、过程检测、文件导入和执行反馈放在第二批，不要求一次完成全部功能。

## 几个关键业务要求

- 用户只有一项有效指标也能分析。少于推荐清单时说明判断范围并建议补测，不强制补齐才能继续。
- 评价要包含存在的问题、可能成因及依据；管理建议应说明适用条件。
- 缺测不能当作正常值，也不能编造综合分数；地图背景与用户实测分开。
- 结果之后可以继续追问或补充检测数据，不能每次都丢失前面的对话和输入。
- 深度模式记录实际执行情况，调整未来检测建议；建议、实际执行和新方案分别保存。
- 示例数据都是虚构 Mock，不能作为实际地块、真实模型效果或科学阈值使用。

## 请先看这几个文件

1. `docs/assessment-api/BACKEND-CHECKLIST.md`：需要确认的事项和排期信息。
2. `docs/assessment-api/README.md`：调用顺序、分工、状态和业务规则。
3. `docs/assessment-api/openapi.json`：具体请求和返回定义，可导入接口调试工具。
4. `docs/assessment-api/examples.json`：35 组请求/返回示例，可对照理解数据结构。

包内还有前端类型定义及校验脚本，方便双方保持字段一致。它们不是已经实现的后端代码。

## 希望后端同学反馈什么

请重点确认：

1. 第一批接口的地址、字段、可空规则和返回格式是否合适。
2. 现有登录、CSRF、数据归属如何复用。
3. 异步任务的状态、轮询、失败重试和重复提交如何处理。
4. 哪些接口已有实现，哪些需要新增，预计何时能提供第一批联调。
5. 后续 N+X 和微调千问的部署方式、支持范围及可用样例。

可以直接在确认清单里填写，也可以整理一份差异意见。前端先按照确认后的约定用 Mock 开发；后端完成后再切换真实接口并共同联调。
